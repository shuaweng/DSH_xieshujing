# Dialogue Diagnostics

对白要同时推进事情、显露人物并改变关系。这个 Skill 只诊断，不修改资产，也不创建 ChangeSet。

## 工作台协议

优先使用本轮 Novel Context Manifest 已物化的对白选区和 `book.style-profile`；不要重复读取相同 Revision。材料仅有坐标时才用 `novel_get` 定点补足，目标缺失时才用 `novel_search` 定位。只读取理解这场交流所需的上下文，不扩展到整本书。若用户随后要求改写，转用 `rewrite-to-style`；场景本身没有冲突时转用 `scene-drive`。

## 六项检查

1. 声音同质化：遮住标签后，能否从词汇、句长、直接程度、回避习惯辨认角色。
2. 生硬：是否人人都说完整、正式、准确的句子，没有打断、停顿、答非所问和动作节拍。
3. 信息倾泻：角色是否解释彼此已知事实，或一人成为设定百科、另一人成为提问机器。
4. 潜台词缺失：角色是否直接宣布感受、企图和主题，言下之意与字面没有距离。
5. 功能单一：对白是否只搬运情报，没有推进、关系变化、人物揭示或权力交锋。
6. 节奏失配：紧张场景是否长篇讲解，情感重场是否没有停顿；轮次是否像机械网球赛。

## 输出要求

先给一句总判断，再列出命中的状态。每项必须引用具体台词，解释它在文本、潜台词或语境哪一层失效，并给修改方向。最后按优先级说明先改声音、信息、隐藏目的还是节奏。不要直接替换原对白，也不要声称工作台内容已被改动。
