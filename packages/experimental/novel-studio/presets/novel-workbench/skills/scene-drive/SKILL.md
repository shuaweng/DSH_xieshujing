# Scene Drive

目标不是在结尾补一句悬念，而是让当前冲突自然产生下一步。

## 工作台协议

使用当前冻结资产优先；从 `novel_list` 查看是否存在 `book.brief`，存在时用 canonical reference 调 `novel_get` 读取准确 Revision，校准当前场景与全书承诺和事实边界。需要补足目标时用 `novel_search` 找章纲或相关正文，用 `novel_get` 读取准确 Revision。设计蓝图和诊断直接回复聊天；用户要求把设计落成章纲时，新建用 `novel_create`、修改用 `novel_propose_changes`；用户明确要求改正文时才对精确正文范围提案。未 applied 的提案绝不等于完成修改。

## 推进诊断

先回答四件事：角色想要什么、谁或什么在阻拦、为什么不能退、结束后必须有什么变化。缺一项，通常就不是句子问题。

选择一到两种核心压力：绝境、两难、对抗、迷雾。阻碍必须压中当前目标，并拥有自己的逻辑。使用基本链条：

`目标 → 压力/阻碍 → 应对与升级 → 结果 → 新不稳定`

结果不能只是事情结束；它应改变处境、关系、认知、资源或风险。章末可落在决定、揭示、威胁、承诺、反转或升级上，但必须来自刚发生的事情，不能靠谜语式留白或作者腔宣布。

## 输出边界

设计模式给推进蓝图、欲望对冲、压力、beat 链、落点和信息边界。诊断模式指出断链位置和最小修复。只有用户明确要求落稿时才创建 ChangeSet，且只改当前目标资产与范围。
