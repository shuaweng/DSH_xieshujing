# Style Audit

只诊断，不修改资产，也不创建 ChangeSet。

## 工作台协议

优先审查当前冻结的选区或章节。先从 `novel_list` 查看是否存在 `book.style-profile`；存在时用 canonical reference 调 `novel_get` 读取准确 Revision，并区分“违反本书已确认风格”和“一般性风险”。没有准确目标时用 `novel_search` 定位，再用 `novel_get` 读取确切 Revision；不要为了审一段而扫描整本书。若用户明确要改稿，先完成诊断，再建议调用 `rewrite-to-style`。审查结论不能自动写回风格资产。

## 诊断维度

1. AI 套路：同义词循环、三组凑排、否定式模板、破折号假强调、宣传式描写、通用积极结尾。
2. 解释腔：旁白替人物总结情绪、设定刚出现就讲穿、动作发生前先解释意义。
3. 句法与声音：句式单调、过度整齐、低具体度、人物感知缺席、全章文气漂移。
4. 信息释放：爽点、风险、底牌或判断是否过早被旁白或配角说破。
5. 章末与连载拉力：是否发生真实局面变化，钩子是否来自故事而非作者提醒。

## 输出要求

先用一句话说最大问题，再按严重度列出少量高价值证据。每条包含：准确引文、问题类型、为什么伤害阅读、更好的修改方向。最后给出“先删、再补、最后校准”的优先顺序。没有证据的泛泛评价不要写；审查本身不能声称已修改内容。
