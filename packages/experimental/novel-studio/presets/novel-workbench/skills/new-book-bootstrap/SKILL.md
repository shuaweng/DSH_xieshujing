# New Book Bootstrap

把模糊想法推进成作者愿意继续写的小说起点。开书是创意共创，不是一次生成大量模板文件，也不是用问卷替作者作决定。

## 项目边界

若用户已明确要求在当前目录开书，而 Novel 工具报告它还不是 Novel Project，使用 `novel_initialize_project` 并传入作品名称。该工具会单独请求用户批准；未批准时不得继续。不得假装已经初始化，也不得用普通文件工具自行制造 `novel.yaml`。用户只是讨论想法、并未要求开书时，不主动初始化目录。

初始化成功后，先用 `novel_list` 查看现有资产与每种类型的创建说明。按标题定位已有材料时用 `novel_search`，读取精确内容时用 `novel_get`。已有资产必须复用，不得创建第二份本书概述、本书风格或同职责书纲。

## 共创顺序

先根据作者已经给出的想法提出一版可讨论的理解，再只追问真正会改变作品方向的问题。通常按以下顺序收敛：

1. **预期锚点**：题材边界、目标读者、最核心的阅读快感或情绪、作者最想写的东西、明确不想出现的套路。
2. **故事发动机**：主角长期欲望、眼前困境、核心阻力、能持续制造选择与代价的机制。世界观只展开到足以支撑冲突的程度。
3. **差异与边界**：金手指或特殊机制的收益、限制与成长空间；人物不能被抹平的矛盾；不能轻易改动的创作红线。
4. **开篇策略**：前三章要兑现什么卖点、让读者形成什么期待、第一章用什么具体事件迫使主角行动。

关键方向不确定时给 2–3 个真正不同的候选，并说明它们各自带来的读者体验、长线空间和代价。不要连续抛出长问卷。每轮结束都用“已确认 / 候选 / 待定”简短归纳，候选和待定内容不能冒充 Canon。

## 工作台资产映射

只创建当前阶段真正有用的资产：

- `book.brief`：自由 Markdown，承载作品定位、读者承诺、核心冲突、主角驱动力、世界边界、已确认事实、候选方向与待定问题。
- `book.style-profile`：自由 Markdown，只记录作者明确确认的叙事距离、句法节奏、对白、信息释放、网文章奏、正向参照与禁用表达。讨论中的风格猜测不能直接写入。
- `planning.outline`：书纲或卷纲的自由 Markdown。书纲处理全书方向；卷纲必须以书纲为 parent。保留作者自己的段落、列表、表格或 beat 结构。
- `planning.chapter-outline`：需要先有对应 `manuscript.chapter`，并以该章节为 parent。只在作者决定规划具体章节时创建。
- `manuscript.chapter`：只有作者明确要求落首章或试写开篇时才创建；创建时在同一次 `novel_create` 调用中提交章节标题与完整正文，不让作者先建立空章节容器。默认在规划资产完成后停下。

人物、地点、灵感、伏笔和开放问题在没有专属 Asset 类型时，先作为概述或大纲中的自由文本章节保存，不发明工具不支持的类型，也不退回旧版平行文件和账本体系。

## 落库协议

在任何创建前，先向作者展示“准备创建或修改哪些资产、每份保存什么”，等待明确确认。新资产使用 `novel_create`；既有资产的正式修改只能基于 `novel_get` 返回的准确 Revision 和 proposalInstructions 调用 `novel_propose_changes`。工具未明确返回 applied 时，只能称为待审提案。

推荐的最小起点是本书概述、经作者确认时的本书风格，以及一份书纲；这只是默认建议，不是阻止作者写正文的门槛。完成后报告每个 canonical reference、Revision 或 ChangeSet，并给出一个最小下一步，例如细化第一卷、建立首章与章纲，或直接开始试写。
