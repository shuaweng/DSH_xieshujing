# Chapter Wrap Sync

把“正文写完了”变成“项目状态也跟着更新了”。

## 核心目标

在章节新增、续写、重写、精修之后，检查并同步项目资产，避免出现：

- 写了很多章，但正式设定没更新
- 写了很多章，但没有章节摘要，后续只能反复回读全部旧正文
- 章节索引缺失，agent 无法低成本理解全书进度
- 上一章章末动作、主角状态、地点、伤势、资源没人记账，下一章开头断气
- 卷纲已经被剧情改坏了，但没人回写
- 已经明确的新信息还留在聊天记录里
- 候选想法被正文误写成正式设定
- 伏笔、未决问题、人物关系变化没人记账

## 何时使用

优先在这些场景使用：

- 刚写完一章正文
- 刚对现有章节做了大改
- 用户说“顺便同步一下设定/大纲”
- 用户担心“写着写着项目文件没更新”
- 续写后需要判断哪些资产应该跟着变

## 不要做的事

- 不要把所有改动都自动写回项目文件。
- 不要把正文里一闪而过、明显还未定的东西直接升格为 `confirmed`。
- 不要重写整份大纲，只做必要同步。
- 不要因为发现 candidate 内容进入正文，就自动当作 confirmed，除非用户明确拍板。
- 不要把章节摘要写成正文复述。
- 不要把未来计划写进章节摘要；章节摘要只记已写正文。

## 工作流

### 步骤 0：确认同步对象

先找到这次刚写或刚改的章节对象：

- 优先读取用户明确点名的章节文件
- 如果用户没给路径，但上下文里有刚编辑过的章节文件，可用该文件作为主对象
- 若对象不明确，先澄清，不要乱猜

### 步骤 1：读取同步所需的最小真源

默认优先读这些资产：

- 当前章节文件
- `PROJECT.md`
- `STYLE.md`（如有）
- `资料/章节索引.md`（如有）
- 当前章对应的 `资料/章节摘要/第XXX章.md`（如有）
- 最近 1-2 章章节摘要（用于连续性承接）
- `资料/事实账本.md`（如有）
- `资料/伏笔账本.md`（如有）
- `资料/连续性账本.md`（如有）
- 相关人物设定
- 相关世界规则
- 当前卷纲 / 章纲
- `脑洞池`
- `未决问题`

只读和本章直接相关的文件，不要无上限扩读。

### 步骤 2：抽取本章带来的“可沉淀变化”

重点检查本章是否产生了这些变化：

1. **章节摘要变化**
   - 本章发生了什么
   - 推进了什么
   - 主角状态如何变化
   - 哪些角色关系变化
   - 新增了哪些事实
   - 埋下或回收了哪些伏笔
   - 下一章必须承接什么

2. **章节索引变化**
   - 本章短索引是否需要新增或更新
   - 是否能让后续 agent 不读全文也知道本章功能

3. **连续性变化**
   - 当前时间线
   - 当前地点
   - 上一章章末动作
   - 主角身体/心理/能力/资源/伤势状态
   - 必须立刻承接的危机

4. **正式设定新增**
   - 角色身份、关系、能力、限制、习惯、伤势、装备
   - 世界规则、系统规则、修行边界

5. **大纲偏移**
   - 实际发生的事与卷纲/章纲不一致
   - 重要事件提前/延后/取消
   - 本章让当前卷目标、最大阻力、核心兑现、卷末变化或下一卷入口发生变化

6. **未决问题已解**
   - 原本 `open` 的问题被正文正式回答

7. **新未决问题出现**
   - 正文新增了后续必须解释的坑

8. **伏笔与线索变化**
   - 新伏笔埋下
   - 旧伏笔回收

### 步骤 3：按状态分类，而不是一把全写

把提取到的变化先分成 4 类：

- `建议写入 confirmed`
- `建议写入 working`
- `建议写入 candidate`
- `建议写入 open`

规则：

- 只有正文明确落地、且不属于悬而未决或试探性信息的，才考虑 `confirmed`
- 与卷内推进、章节计划相关的，优先 `working`
- 只是延伸想法、可能分支、临时设想，进 `candidate`
- 新产生但未解的问题，进 `open`

### 步骤 4：先给同步摘要，再决定是否落盘

默认先输出一个简短同步摘要，包含：

- 当前章摘要应如何写
- 章节索引应新增/更新什么
- 连续性账本应更新什么
- 本章新增了哪些可沉淀信息
- 哪些文件建议更新
- 每个文件建议写入什么
- 哪些内容**不应**写入正式设定

如果用户明确要求“直接同步”，再落盘。
如果用户没授权直接写，先给摘要和建议，不自动动所有文件。

例外：如果本 skill 是由 `chapter-execution` 在“正式正文已写入项目文件”之后接续触发，视为同一次正文任务的必要收尾，可以直接更新章节摘要、章节索引和连续性账本；但人物、世界规则、卷纲等高影响文件仍按最小必要原则更新。

### 步骤 5：执行最小同步

若用户允许写入，则按“最小必要修改”执行：

- 只改真正受影响的文件
- 必须优先更新章节摘要、章节索引、连续性账本
- 尽量追加或局部编辑，不整份重写
- 保持 frontmatter 不被破坏
- 更新后简短汇报：
  - 改了哪些文件
  - 分别新增/修正了什么
  - 哪些风险仍未处理

### 步骤 5.5：检查是否需要蒸馏写作偏好

同步完成后，检查 `.lingtai/revisions/` 下已有几章 revision 记录（`第NNN章.jsonl`）。

- 若已有 ≥3 章记录，在收尾汇报里加一句：
  > 我注意到你最近改了不少稿，要不要让我用 style-distill 蒸馏一下你的写作偏好？
- 不要自动执行 style-distill，只提醒，由用户决定。

## 建议优先同步的资产

> 各资产的**模板与字段**统一见 `new-book-bootstrap/references/asset-templates.md`，此处不再重复贴模板。
> 下表只说"何时更新 + 写入要点"。前 3 项（摘要/索引/连续性账本）是每章必更的核心，其余按本章是否真正触及来定。

| 优先级 | 资产 | 何时更新 | 写入要点 |
|---|---|---|---|
| 必更 | `资料/章节摘要/第NNN章.md` | 每章写完 | 写给下一章 agent 看，不复述全文、不写未来计划；改写导致旧摘要失真必须覆盖 |
| 必更 | `资料/章节索引.md` | 每章写完 | 单章 100-200 字，只记已发生事实，不写成长大纲 |
| 必更 | `资料/连续性账本.md` | 每章写完 | 时间线、地点、章末动作、主角身心/资源/伤势、待承接危机、短期目标、不能忘的限制 |
| 触及才更 | `资料/伏笔账本.md` | 埋下/升级/揭示/兑现/废弃伏笔时 | 更新状态 `planted/escalated/revealed/paid_off/abandoned` 及读者/主角已知 |
| 触及才更 | `资料/事实账本.md` | 确认硬事实时 | 只录正文明确落地的世界规则/能力边界/资源道具/角色硬状态/已公开信息 |
| 触及才更 | 人物设定 | 角色正式信息变化时 | 身份/关系/能力/限制/伤势/装备/稳定习惯 |
| 触及才更 | 世界规则 / 系统规则 | 硬规则被验证/暴露/修正时 | 更新对应规则文件 |
| 触及才更 | `大纲/卷纲.md` / 章纲 | 实际剧情偏离计划且影响后续时 | 只改 working 大纲，按下方"更新卷纲时至少检查 7 项" |
| 触及才更 | `大纲/脑洞池.md` | 冒出"以后也许能用"的想法时 | 写入 `candidate`，未拍板不升 confirmed |
| 触及才更 | `大纲/未决问题.md` | 正文新增必须后续解释的坑时 | 写入 `open` |

## 输出格式建议

默认先输出：

```md
## 本章同步摘要

- 建议更新文件：
  - ...
- 章节摘要：
  - ...
- 章节索引：
  - ...
- 连续性账本：
  - ...
- 建议写入 confirmed：
  - ...
- 建议写入 working：
  - ...
- 建议写入 candidate：
  - ...
- 建议写入 open：
  - ...
- 暂不建议同步：
  - ...
```

## 判断边界

### 什么时候不要写入 `confirmed`

- 角色只是猜测、怀疑、误判
- 旁白故意留白
- 明显是伏笔，不是事实
- 来自 candidate 脑洞而未正式确认

### 什么时候应该更新卷纲

- 本章剧情已经改变后续安排
- 重要事件顺序变化
- 某条支线被确认或废弃
- 本章实际解决方案和卷纲规划的主解法不同，且这种差异会影响后续爽点排布
- 本章章末钩子打开了新方向，原卷纲的下一章入口已经失效
- 连续两章实际推进都偏离卷目标，说明卷纲需要回到 `outline-beat-design` 重排

### 更新卷纲时至少检查 7 项

不要只改一句章节摘要。卷纲同步时至少检查：

1. 本卷目标是否仍成立
2. 最大阻力是否变化
3. 核心兑现是否提前、延后或换形态
4. 卷末地位 / 关系 / 认知变化是否需要调整
5. 下一卷入口是否仍自然
6. 爽点节奏是否出现真空或扎堆
7. 后续 3-5 章职责是否需要重排
