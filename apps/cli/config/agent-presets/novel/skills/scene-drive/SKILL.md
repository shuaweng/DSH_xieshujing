# Scene Drive

不是“事后补一句狠话”的章末修补 skill。

它负责把一场戏或一章的**推进链**搭对，让钩子在写的时候自然长出来。

## 核心判断

好钩子通常不是作者出来宣布“大事要来了”，而是当前冲突跑完以后，自然留下：

- 新问题
- 新风险
- 新决定
- 新揭示
- 新升级

所以本 skill 的重点不是“修悬浮句”，而是：

1. 让主角有清楚目标
2. 让阻碍真的顶上来
3. 让结果带来变化
4. 让章末停在一个读者会自然翻页的位置

## 何时使用

优先在这些场景使用：

- “这章有事，但不够想看下一章”
- “这一段太平了，帮我加张力”
- “章末收不住，只能靠作者腔硬抬”
- “帮我设计这场冲突 / 这一章的推进链”
- “这章该停在哪里才对”
- “先别重写，先告诉我这章为什么发虚”

## 不要做的事

- 不要把它做成单纯的“章末补钩子”。
- 不要为了制造拉力，硬塞旁白式悬念句。
- 不要只加风险，不加角色目标和不能退的理由。
- 不要只追求“悬”，却没有实质变化。
- 不要把段落切碎当成节奏本身。

## 工作流

### 步骤 0：判断你在处理什么

先判断当前任务是：

- 单场戏设计
- 单章推进设计
- 开头/前三章推进设计
- 已有片段的“发平”诊断
- 已有片段的定向重写

如果用户只是要审稿，不直接生成方案：

- 章末/中段审稿优先接 `style-audit`
- 开头/前三章审稿优先接 `opening-review`
- 连续几章或卷内节奏审稿优先接 `pacing-audit`
- 信息释放边界与说破太早审稿优先接 `info-release-check`
- 如果先缺卷 / 章规划而不是缺单章推进链：优先接 `outline-beat-design`

## 步骤 1：明确推进链起点

至少先写清楚这 4 件事：

1. 主角这一场 / 这一章想要什么
2. 谁或什么在拦他
3. 他为什么不能退
4. 这场结束后必须发生什么变化

如果这四件事说不清，通常不是“钩子弱”，而是整场戏骨架没立住。

### 步骤 2：选压力类型

从 `references/conflict-and-propulsion.md` 里选 1 到 2 种核心压力：

- 绝境（不得不跑）
- 两难（不得不选）
- 对抗（不得不打）
- 迷雾（不得不猜）

不要贪多。比起四种压力全上，更重要的是：

- 这一种压力是否真的压到了主角当前目标
- 阻碍方是否有独立逻辑

如果需要从零设计一段冲突，用 `references/conflict-and-propulsion.md` 的 **4 步冲突设计工作流**：
1. 确立双方欲望（欲望对冲分析）
2. 选择压力象限（1-2 个，可叠加）
3. 设置主角锚点（为什么不能退）
4. 推演冲突结果（成长代价 + 实质变化）

### 步骤 3：搭推进链

默认用这条链：

`目标 -> 阻碍/压力 -> 应对 -> 结果 -> 新的不稳定`

**冲突弧线与厚度校准（evolved: 2026-05-10）**：
- **完整弧线**：确保链条中包含“铺垫-情绪-爆发”的完整过程。
- **前后对比设计**：在“阻碍/压力”环节强化对主角的轻视或压制，在“结果”环节突出反杀带来的认知震撼。
- **字数厚度预估**：设计时需确保博弈回合足够多（至少 3-4 个往返），以支持 3000 字左右的正文体量。

其中最后一段最关键：

- 结果不能只是“事情结束了”
- 必须留下一个新的不稳定状态

这个“不稳定”就是下一章拉力的来源。

#### 替代框架：Scene-Sequel 节拍（适合需要情感消化的场景）

如果当前场景需要兼顾紧张推进和情感消化，可以用 Swain 框架：

**Scene（场景）**：`目标 → 冲突升级 → 灾难`
- 目标：POV 角色在这个场景中想要什么？必须具体、可感知
- 冲突升级：阻力逐步加码，不能静态对抗——每一个 beat 都让目标更难达到
- 灾难：场景结束时的结果（按叙事力度排序）：
  - “是的，但是……” → 目标达成，但带来新问题（最强）
  - “不，而且……” → 目标失败，局面更糟
  - “不” → 单纯失败
  - “是” → 成功（慎用——会泄掉张力）

**Sequel（续篇）**：`反应 → 困境 → 决定`
- 反应：对灾难的情绪消化（读者也在消化）
- 困境：角色面临两难——前路都有代价
- 决定：角色做出选择 → 这个决定变成下一个场景的目标

**节奏控制**：
- 场景多、续篇少 → 快节奏、动作密集
- 续篇多、场景少 → 慢节奏、沉浸内省
- 关键技巧：通过压缩/展开续篇来调节节奏

### 步骤 4：决定章末落点类型

不要默认只会做 cliffhanger。

更常用的章末落点是：

- `question`
- `decision`
- `revelation`
- `threat`
- `promise`
- `reversal`
- `escalation`

选择标准：

- 必须和当前人物目标或当前风险直接相关
- 必须来自刚发生的事情
- 不能靠作者替故事发力

### 步骤 5：锁信息释放边界

明确三件事：

1. 哪些效果现在就该给读者看到
2. 哪些原理现在不能讲穿
3. 哪些判断不能让配角太早替读者说完

如果一章之所以“没钩子”，常见真实原因不是结尾太弱，而是：

- 结果刚出来，原理就被讲完了
- 风险刚抬头，就被旁白总结掉了

### 步骤 6：落执行约束

真正写的时候，至少守住这些节奏规则：

- 动作、对话、转折段要短
- 关键句单独一行
- 关键信息放段首或段尾
- 章末最后一句尽量短、硬、具体
- 不要把翻页理由埋在解释段后面

更细的移动端节奏规则见 `references/rhythm-and-landings.md`。

### 步骤 7：决定输出方式

如果用户要“先设计再写”：

- 先给一份推进蓝图
- 不直接重写全文

如果用户要“按这个方向直接改”：

- 只改当前目标片段
- 明确这次主要调整的是：
  - 冲突
  - 结果
  - 章末落点
  - 节奏

## 和其他 skill 的关系

- 开头/黄金三章审稿：`opening-review`
- 风格/AI 味/假钩子审稿：`style-audit`
- 对话层专项诊断：`dialogue-diagnostics`
- 多章节奏 / 追读审稿：`pacing-audit`
- 信息释放顺序 / 解释欲审稿：`info-release-check`
- 卷纲 / 分章 / beat 规划：`outline-beat-design`
- 真正落正文：`chapter-execution`
- 写后同步：`chapter-wrap-sync`

默认关系是：

- `opening-review` / `style-audit` 负责看出问题
- `character-arc` 负责角色弧线诊断
- `scene-drive` 负责把推进链搭对
- `chapter-execution` 负责真正落稿
