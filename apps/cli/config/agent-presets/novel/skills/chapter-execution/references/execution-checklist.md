# Chapter Execution Checklist

这份参考用于正文执行前后自检。

## 一、执行前必须明确的 5 件事

1. 这章要推进什么
2. 哪些设定绝不能碰
3. 哪些信息不能提前说破
4. 本项目此刻要什么风格
5. 这章最后应该停在哪里

## 二、续写时最容易犯的错

- 忽然改掉叙述温度
- 明明该推进，却开始解释世界观
- 新设定突然冒出来
- 为了埋钩子，用作者腔硬宣布大事

## 三、改写时最容易犯的错

- 改着改着把剧情也改了
- 用户要“更冷”，结果写成更空
- 用户要“更顺”，结果只是更短
- 解释没少，信息还变得更散

## 四、收紧时最优先删的东西

1. 重复解释
2. 重复心理
3. 没有推进功能的气氛句
4. 作者替读者总结的句子

## 五、章末钩子检查

问自己：

- 结尾有没有明确的继续读理由？
- 钩子是不是和当前人物目标或风险强相关？
- 是自然长出来的，还是作者站出来宣布？

## 六、新章节重复疲劳检查

如果你在写新章节，至少问自己：

- 近两章的主冲突类型是不是和这章一样？
- 近两章的主 arena 是不是和这章一样？
- 主角这次是不是又靠同一招过关？
- 这章的变化是不是只是“赢更多 / 热度更高 / 敌人更狠”？
- 这章章末是不是又在用同一种悬念口气？

如果近 3 章里有两项以上重复，优先停下来：

1. 先接 `outline-beat-design` 重排章职责
2. 再接 `scene-drive` 给当前章换压力结构和落点

## 七、完成后如果出现这些情况，建议接 `chapter-wrap-sync`

- 主角能力边界被明确
- 新规则被正式验证
- 卷纲里的事件顺序变了
- 新坑埋下了
- 某个未决问题被正文坐实了
