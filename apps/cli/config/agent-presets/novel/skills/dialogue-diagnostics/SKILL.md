# Dialogue Diagnostics

不是替用户重写对话，而是先判断：**这段对话到底哪里不像人在说话、哪里把戏剧性杀掉了。**

## 核心原则

对话必须同时做不止一件事，否则对于小说而言就太惰性了。

好的对话同时推进情节、揭示角色、建立张力、确立人物关系动态并创造潜台词。如果对话只是在传递信息，那它就是失败的。

## 三个层次

每一行对话在三个层次上运作：

| 层次 | 定义 | 检查要点 |
|:---|:---|:---|
| 文本 | 字面上说了什么 | 是否具有角色特征？是否精炼？节奏是否自然？ |
| 潜台词 | 话语之下的含义 | 说出的和意指的之间是否存在差距？ |
| 语境 | 什么塑造了这次交流 | 权力动态？历史？每个角色想要什么？ |

当对话失败时，通常是在潜台词层（没有潜台词）或文本层（声音没有区分度）上出了问题。

## 何时使用

- "帮我看看这段对话为什么没劲"
- "这几个角色说话是不是像同一个人"
- "对话是不是变成讲课了"
- "这段对白的潜台词够不够"
- "打脸/传承/宗门对话怎么写才对味"
- "古风对话是不是穿帮了"

## 不要做的事

- 不要直接改对白。先诊断，再给方向。
- 不要只说"可以更生动"。必须指出具体哪一句、哪个 D 状态。
- 不要把所有对话问题都归为"AI 味"。对话有自己的 7 个诊断状态。
- 不要忽略网文特有的对话模式——装逼打脸、师徒传承、系统面板、宗门势力各有写法。

## 工作流

### 步骤 0：判断对话类型

先判断这段对话属于什么场景：

- 日常交代
- 冲突对峙
- 装逼打脸
- 师徒传承 / 知识传递
- 系统 / 面板交互
- 宗门 / 势力博弈
- 争吵 / 情绪爆发
- 试探 / 诱惑 / 说谎

不同场景的优先检查重点不同。

### 步骤 1：先给一句总判断

用一句话说清最大问题：

- "这段对话最大的问题是所有角色说话像同一个人（D1），不看标签分不出谁是谁。"
- "对话变成了设定讲座（D3 设定百科型），角色 B 连说了五句纯设定。"
- "对话太直白（D4），反派直接说了自己的企图，没有潜台词。"

### 步骤 2：按 D1-D6 诊断

逐条扫描以下 6 个诊断状态，标记命中的项：

#### D1. 同质化的声音

所有角色听起来一样。遮住对话标签后说话者无法区分。

**诊断清单：**
- [ ] 角色之间的词汇范围有差异
- [ ] 句子复杂度因角色而异
- [ ] 直接程度不同（直率 vs. 委婉）
- [ ] 每个角色都有不会说的话或回避的话题
- [ ] 不同势力/出身的角色有辨识度明显的语言风格
- [ ] 不同修为层次的角色谈吐有质的差异

**干预：** 为每个角色建立语言模式档案，给每人一个口头习惯和一个言语回避。

#### D2. 生硬的对话

对话僵硬、正式、不自然。角色说的都是完整的语法句子，没有片段、打断、答非所问。

**诊断清单：**
- [ ] 角色适当地使用缩写和口语
- [ ] 部分句子不完整或被打断
- [ ] 对话有节奏变化（不是节拍器式的）
- [ ] 角色偶尔会答非所问

**干预：** 朗读每一行——如果你无法自然地说出来，就重写。

#### D3. 信息倾泻

对话被用来搬运信息，而不是交锋。两个常见子型：

- **a. 双方已知型**：角色解释彼此都已经知道的事，一方提问只为让另一方解释（"如你所知……"）。
- **b. 设定百科型（网文高发）**：角色大段解释世界设定、修炼体系、势力分布，一个变成"设定百科全书"，另一个沦为提问机器。

**诊断清单：**
- [ ] 没有"如你所知……"式结构
- [ ] 角色对信息有分歧，而非单向转述
- [ ] 没有角色连续说超过三句纯设定信息
- [ ] 信息从冲突或情感变化中浮现，而非说教
- [ ] 设定通过角色体验展开，暂不需要的信息推迟到需要时才出现
- [ ] 读者尽可能与角色一起发现

**干预：** 在信息里找冲突，让角色产生分歧；把"讲"变成"发现"；大段设定拆碎分散到多章，用冲突包裹信息。

#### D4. 没有潜台词（直白式）

角色直接说出自己的意思、感受和想要的。表面和含义之间没有差距。

**网文要点：** 反派不要直说"我要杀了你，夺走你的宝物"。更好的写法——"林兄最近机缘不浅啊，不知可否借来一观？" 前者白开水，后者有张力。

**诊断清单：**
- [ ] 情绪状态通过行为展示，而非宣告
- [ ] 角色想要他们无法直接要求的东西
- [ ] 肢体语言可以与言语矛盾
- [ ] 未说出的与说出的同样重要

**干预：** 给每个角色在每次对话中设定一个隐藏目的。

#### D5. 单一功能对话

对话只完成一件事（通常是情节信息），没有关系转变、角色揭示或张力。

**双重职责测试 — 至少答出三个：**
1. 这对情节有什么作用？
2. 这揭示了角色的什么？
3. 潜台词是什么？
4. 这如何影响人物关系？

**干预：** 拒绝单一功能对话——总是添加第二个目的。

#### D6. 节奏不匹配

对话节奏与场景需要不匹配。紧张时刻有悠闲的交流，平静时刻有快速的对白。

| 快节奏 | 慢节奏 |
|:---|:---|
| 短交流 | 较长的独白 |
| 极少/无标签 | 描写停顿 |
| 无动作节拍 | 台词之间有动作节拍 |
| 打断 | 嵌入反思 |

**干预：** 随着张力上升加快对话，为情感分量放慢。

### 步骤 3：检查网文特有模式

如果是网文，额外检查以下 4 种特有对话模式。这些模式本身不是反模式——用好了是爽点利器，用差了变成套路注水。

更详细的模式说明和写法指南见 `references/webnovel-dialogue-patterns.md`。

- **装逼打脸对话** — 反派嘲讽是否精炼？主角反击是否有记忆点？围观是否变成复读机？
- **师徒/传承对话** — 是否滑入 D3 设定百科型？老师是否连说十句设定？
- **系统/面板对话** — 系统提示是否简洁有力？主角吐槽是否有人格体现？
- **宗门/势力对话** — 身份等级是否影响语言？会议是否体现权力博弈？

### 步骤 4：检查反模式

逐一扫描以下反模式（详见 `references/webnovel-dialogue-patterns.md`）。"信息倾泻"已并入 D3，此处不再单列：

1. **双胞胎** — 所有角色用相同词汇和节奏
2. **庭审记录员** — 太真实但戏剧性已死
3. **情绪旁白者** — "他震惊道""她恐惧道"
4. **哲学家** — 角色替作者讲主题
5. **网球赛** — 完美交替、无权力差异
6. **复读机围观（网文特有）** — 每次打脸后围观群众轮流震惊

### 步骤 5：输出诊断报告

默认输出格式：

```md
## 总判断

[一句话说清最大问题]

## 命中的诊断状态

### D?. [状态名]
- 具体问题句：
- 为什么有问题：
- 更好的方向：

## 网文模式检查
- [模式]：[是否命中 + 原因]

## 反模式命中
- [反模式名]：[具体位置]

## 优先修改顺序
1. ...
2. ...
3. ...
```

## 对话标签使用规范

中文网文对话标签的克制原则：

- 一段对话中，**70% 以上**用"道""说道"或无标签
- 情绪标签（"怒吼道""惊呼道"）是调味料，不是主菜
- 如果台词本身已经传递了情绪，标签就不要重复——"滚！"不需要写成"他愤怒地大喊道"
- 连续对话中可以省略标签，用动作节拍代替

## 判断边界

### 什么时候不要误判

- 角色本来就是话多型、解释型人设
- 师父设定就是那种爱讲课的老顽固
- 系统面板本身就是信息载体

### 什么时候一定要判高风险

- 一段对话中有超过三句连续纯设定解说
- 不看标签完全分不出谁在说话
- 反派直接说出企图，毫无潜台词
- 对话结束后局面零变化
