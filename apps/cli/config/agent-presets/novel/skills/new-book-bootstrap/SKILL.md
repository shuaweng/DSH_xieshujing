# New Book Bootstrap

把“一个点子”变成“一个能持续协作的小说项目”。

## 核心原则

- 默认先建**最小创作资产**，再写正文。
- 默认先把信息分成：
  - `已确认`
  - `候选`
  - `未决`
- 默认把长篇上下文做成**章节资产账本**：正文保持干净，摘要、索引、事实、伏笔单独沉淀。
- 用户明确要求继续写正文之前，先把项目最少需要的文件落起来。
- 如果项目里已经有资产，优先**补齐 / 更新**，不要粗暴重写。
- `candidate` 不能直接升格为 `confirmed`，除非用户明确拍板。

## 何时使用

用户出现以下意图时，优先加载本 skill：

- “我想写一本小说 / 网文 / 长篇”
- “帮我把这个点子整理成项目”
- “先别急着写正文，先把设定和大纲搭起来”
- “给我起 AGENTS.md / PROJECT.md / STYLE.md / 大纲 / 设定”
- “新书初始化 / 开新书 / 建新项目”

## 不要做的事

- 不要一上来直接吐完整正文。
- 不要在没区分 `confirmed / candidate / open` 的情况下就写正式设定。
- 不要把用户随口脑暴自动写进正式 canon。
- 不要在已有项目里盲目覆盖现有 `AGENTS.md / CLAUDE.md / PROJECT.md / STYLE.md / 设定 / 大纲`。

## 工作流

### 步骤 0：检查项目现状

先检查当前目录里是否已有这些资产：

- `AGENTS.md`
- `PROJECT.md`
- `STYLE.md`
- 人物设定类文件
- 世界规则类文件
- 卷纲 / 章纲类文件
- 章节索引 / 章节摘要 / 事实账本 / 伏笔账本 / 连续性账本
- 脑洞池 / 未决问题类文件

如果已存在：

- 先读它们
- 判断是补齐缺失、还是更新已有资产
- 不要默认全部重建

### 步骤 1：预期锚定

在收集任何设定之前，先帮用户锚定"预期"——这本书最核心的愿景和执念。

**做法**：

- 如果用户已经提供了大量信息，从中提炼预期，让用户确认
- 如果用户只有一句话点子，用 3-5 个高杠杆问题引出预期
- 不要让用户填表——用自然对话带出

**必须覆盖的预期维度**（不必一次问完，自然带出即可）：

1. 题材边界：想写什么？不碰什么？
2. 核心体验：读者最该获得什么体验？
3. 个人执念：一定要写进去的元素
4. 绝对不要：讨厌的、不想出现的东西

**输出**：整理成 `预期.md` 草稿，让用户确认。

**【重要】** 后续每个子步骤完成后，Agent 应快速对照预期确认方向没跑偏。

### 步骤 2：交互式创意共创

**核心原则**：这一步是多轮对话，不是一次性收集后直接生成。每个子阶段产出后须经用户确认再进入下一个。

参考框架见 `references/creative-facilitation.md`。

#### 步骤 2A：世界观与核心设定

用对话方式逐步打磨：

- 世界类型与基调
- 力量/修炼体系（至少定义 3-6 个大境界，每个有质变标志）
- 核心规则与限制
- 主要势力结构

**Agent 手段**：不要空问"你的世界观是什么"。应该基于用户已有信息先草拟一版，展示给用户，再逐项调整。如果用户给的信息太少，挑世界观十问中最关键的 2-3 个来问（见 `references/creative-facilitation.md` 第三部分）。

**【暂停确认】** 世界观敲定后，让用户确认再继续。

#### 步骤 2B：金手指深度设计

金手指是网文命脉，不能只收集"一句话核心机制"。按 5 个维度逐一打磨：

1. **核心概念**：本质、来源、独有性
2. **功能模块**：前期/中期/后期各解锁什么
3. **平衡性设计**：代价、限制、副作用
4. **进化路线**：1.0 → 2.0 → 3.0 的质变逻辑
5. **视觉/感知表现**：在文中怎么呈现

详细框架见 `references/creative-facilitation.md` 第一部分。

**Agent 手段**：先根据 2A 的世界观和用户的核心点子草拟金手指初稿，再逐维度确认和打磨。

**【暂停确认】** 金手指定稿后，让用户确认再继续。

#### 步骤 2C：角色深度设计

为主角和核心配角建立有深度的人设，不只是"名字+身份+性格标签"。

**主角必须覆盖**：

1. **核心三要素**：欲望、难点、成就
2. **角色弧线**：谎言 → 想要 → 需要（建议从四种网文经典弧线中选择或混搭）
3. **A面/B面**：表面性格 vs 真实一面
4. **语言风格**：说话方式和用词习惯
5. **拒绝降智原则**：这个角色绝对不会做的蠢事

**核心配角/反派**（至少 1-2 个）：

- 与主角的利益关系
- 核心驱动力
- 性格弱点

详细框架见 `references/creative-facilitation.md` 第二部分。

**Agent 手段**：先从用户已有信息草拟角色卡，再用框架中的维度逐项补充。常见网文谎言库可以直接推荐给用户选用。

**【暂停确认】** 核心角色定稿后，让用户确认再继续。

#### 步骤 2D：创作红线

根据前面的讨论，整理本项目的"绝对不能做"：

- 通用红线（禁止水文、降智等）
- 项目特有红线（根据题材和用户偏好）
- 角色红线（主角绝对不做的事）

**Agent 手段**：根据前面 2A-2C 的讨论，主动提炼 3-5 条关键红线建议，让用户确认或补充。红线少而精，不要列一大堆。

**【暂停确认】** 红线确认后，进入下一步。

### 步骤 3：在聊天里整理 Bootstrap Brief

在真正写文件前，先输出一份简短整理，汇总步骤 1-2 的共创成果：

- `已确认`：经用户拍板的设定
- `候选`：有想法但还没定的
- `未决`：需要后续验证的
- `建议生成的项目资产`
- `预期对照`：当前方向是否符合步骤 1 的预期

如果用户已经明确说“可以直接帮我建”，则这一步可以简短，但仍要先把状态分清。

### 步骤 4：生成最小项目资产

默认最小资产集：

- `预期.md`
- `AGENTS.md`
- `PROJECT.md`
- `STYLE.md`
- `资料/人物设定.md`
- `资料/世界规则.md`
- `资料/创作红线.md`
- `资料/章节索引.md`
- `资料/章节摘要/README.md`
- `资料/事实账本.md`
- `资料/伏笔账本.md`
- `资料/连续性账本.md`
- `大纲/卷纲.md`
- `大纲/前三章作战图.md`
- `大纲/脑洞池.md`
- `大纲/未决问题.md`

如用户已经准备直接进入写稿，再额外创建：

- `正文/第01章.md`

但注意：`正文/第01章.md` 默认只需要是**章节入口或草稿骨架**，不必直接生成整章。

生成这些文件时：

- `AGENTS.md` / `PROJECT.md` / `STYLE.md` 按本 skill 的参考模板起草（`AGENTS.md` 兼容 Claude Code：如需可复制为同内容 `CLAUDE.md`）
- 结构化项目文件按 source metadata/frontmatter 标注角色和状态
- `预期.md` 用 `confirmed`
- `资料/人物设定.md`、`资料/世界规则.md` 用 `confirmed`
- `资料/创作红线.md` 用 `confirmed`
- `资料/章节索引.md` 用 `working`
- `资料/章节摘要/README.md` 用 `working`
- `资料/事实账本.md` 用 `confirmed`
- `资料/伏笔账本.md` 用 `working`
- `资料/连续性账本.md` 用 `working`
- `大纲/卷纲.md` 用 `working`
- `大纲/前三章作战图.md` 用 `working`
- `大纲/脑洞池.md` 用 `candidate`
- `大纲/未决问题.md` 用 `open`

模板与字段建议见：

- `references/asset-templates.md`
- `references/style-seeds.md`
- `references/creative-facilitation.md`

### 步骤 5：写完后给下一步，不默认直接写正文

默认给用户 2 到 3 个自然下一步，例如：

- 先细化第一卷卷纲
- 先把主角和外挂边界压实
- 先设计第 1 章开篇路线

不要默认直接跳到“我来给你写第一章完整正文”，除非用户明确要求。

## 资产生成规则

> 各资产的**模板、字段、骨架代码块**统一见 `references/asset-templates.md`（17 类资产全覆盖）。
> 本节只说每个资产的**职责定位**和**关键护栏**——即"它为什么存在、不能写成什么样"。起草时按 reference 模板填充。

### `AGENTS.md`（工作流路由与协作护栏）

定义项目默认工作流、不同任务接哪个 skill、写正文前先读哪些资产。

护栏：它不是世界观真源/角色设定集/剧情摘要，不要把具体设定情节塞进来；写新章禁止默认读全部旧正文，应优先读 `资料/章节索引.md`、近期摘要、上一章正文和必要账本。

### `PROJECT.md`（这本书是什么）

定义核心卖点、已确认设定、协作规则、真源与状态边界。

### `STYLE.md`（想写成什么气质）

定义表达与节奏护栏、开头与黄金三章起法、禁止的 AI 味、钩子埋法、信息释放边界、章节推进与移动端排版。

### `大纲/卷纲.md`（每章为什么必须写）

定义当前卷为什么存在、每章为什么必须写。默认至少先做第一卷 working 版，不要等正文写崩再补。每卷须覆盖：本卷目标、最大阻力、核心兑现、卷末变化、下一卷入口、爽点节奏、章节职责（模板见 reference）。

护栏：卷纲不是设定集；它是正文执行的上游约束。第 4 章后若无当前卷纲，优先补卷纲，不要裸续写。允许 working，但必须能回答"下一章为什么必须存在"。

### `大纲/前三章作战图.md`（开篇三章功能分工 + 防重复护栏）

定义前三章各自任务、每章主冲突/arena/解法/变化、章末钩子类型、哪些冲突/解法/收口模板不能连续复用。

护栏：它不是长大纲也不是正文骨架，只钉死开篇三章的功能分工和防重复护栏。默认起一版草图。若发现三章职责不清、冲突类型重复、打脸模板连刷，先接 `outline-beat-design`；需给单章补压力落点时再接 `scene-drive`。

### `资料/章节索引.md`（全书每章状态的极短账本）

用每章 100-200 字记录"发生了什么、推进了什么、留下什么钩子"，让写新章时不用回读全部旧正文。

护栏：只写正文已落地的信息，不把候选脑洞/作者计划伪装成正文事实。写第 4 章以后，`chapter-execution` 默认先读这里而非扫全书旧正文。

### `资料/章节摘要/`（长篇续写的主要上下文来源）

每章写完后创建 `第NNN章.md`，覆盖 9 个维度（发生了什么、剧情推进、主角状态、关系变化、新增事实、伏笔、爽点情绪、下一章承接、连续性禁区——字段见 reference）。

护栏：摘要不是复述全文，是给后续 agent 用的剧情账本；写作注意事项要和正文事实分开；写新章默认只读最近 2-3 章摘要，不要全文塞进上下文。

### `资料/事实账本.md`（不能随便改的硬事实）

记录正文已确认的世界规则、能力边界、资源数量、道具状态、伤势代价、组织关系、已公开信息。

护栏：只有正文明确落地的才能进；角色猜测、误判、谎言、旁白留白不能当 confirmed。

### `资料/伏笔账本.md`（伏笔生命周期）

记录每条伏笔的状态（`planted / escalated / revealed / paid_off / abandoned`）、读者已知、主角已知、真相、回收窗口（字段见 reference），避免埋了不回、回了忘记同步。

### `资料/连续性账本.md`（防新章开头断气）

记录跨章易断的连续性信息：当前时间线、上一章章末动作、当前地点、主角身心资源状态、重要角色位置、必须立刻承接的危机、不能遗忘的短期目标。

护栏：它不是大纲，是防止新章开头断气、跳场、忘伤、忘人、忘倒计时的工作文件。

### 结构化标注与状态边界

`资料/` 与 `大纲/` 下重要文件优先用 frontmatter 标注 `doc_role / truth_status / priority / source_scope`（格式见 reference）。状态边界：`confirmed` 正式设定 / `working` 工作版本 / `candidate` 候选脑洞 / `open` 未决问题。

## 写正文前的最低门槛

如果用户要开始写正文，至少应满足：

- 已有 `预期.md`
- 已有项目级 `AGENTS.md`
- 已有 `PROJECT.md`
- 已有 `STYLE.md`
- 已有主角正式设定（含核心三要素和弧线）
- 已有金手指设定（至少覆盖核心概念和平衡性）
- 已有 `资料/章节索引.md`
- 已有 `资料/章节摘要/` 目录或等价章节摘要区
- 已有 `资料/事实账本.md`
- 已有 `资料/伏笔账本.md`
- 已有 `资料/连续性账本.md`
- 已有当前卷 `大纲/卷纲.md` 或等价卷纲文件
- 如果要写前 3 章，必须已有 `大纲/前三章作战图.md` 或等价黄金三章规划
- 如果要写第 4 章及以后，必须已有当前卷卷纲；缺卷纲时先用 `outline-beat-design` 补齐

如果这些都没有，优先补资产，不要裸写。
