# Bootstrap Asset Templates

这份参考用于生成新书初始化时的最小项目资产。

## 1. `AGENTS.md`（兼容 CLAUDE.md）

建议最少包含：

1. 项目协作定位
2. 默认工作流路由
3. 写正文前必读资产
4. 不同问题该优先接哪个 skill
5. `AGENTS.md` 与 `PROJECT.md / STYLE.md / 资料 / 大纲` 的边界

推荐最低骨架：

- 这是一部小说 / 网文项目，默认先走项目资产，不裸写正文
- 新点子 / 开坑意图：先接 `new-book-bootstrap`
- 卷纲 / 分章 / beat 规划：先接 `outline-beat-design`
- 章节起草 / 续写 / 重写：先接 `chapter-execution`
- 单章推进链发虚 / 章末落点无力：先接 `scene-drive`
- 开头 / 第一章 / 黄金三章审稿：优先接 `opening-review`
- 风格 / AI 味 / 对白审稿：优先接 `style-audit`
- 多章节奏 / 卷内推进审稿：优先接 `pacing-audit`
- 信息释放 / 解释欲 / 说破太早：优先接 `info-release-check`
- 章节完成后同步 canon / 卷纲 / 未决问题：优先接 `chapter-wrap-sync`
- 真正写正文前，默认先读 `PROJECT.md`、`STYLE.md`、相关 confirmed 真源、当前卷纲 / 章纲、`资料/章节索引.md`、最近 2-3 章摘要、上一章正文和必要账本
- 写新章时禁止默认读取全部旧正文；需要旧章细节时，先查 `资料/章节索引.md` 和 `资料/章节摘要/`，再定点读取对应旧章全文
- 不要把具体设定、剧情真相或角色档案长期堆在 `AGENTS.md`；这些应写入对应正式资产

**写作硬门禁**（建议原样写进新项目 `AGENTS.md`，作为每章都生效的兜底铁律；这些是"软约束兜底"，弱模型最容易在 skill 没触发时违反）：

1. **一次只写一章**——除非用户明确要求连写，默认单章落稿后停下做同步，不连续狂写多章。
2. **禁裸写正文**——简报 / 卷纲 / 前三章作战图还是空模板时，先补资产，不从宽泛首轮请求直接起草正文。
3. **死守主角近景限知视角**——同一场景内不开上帝视角写敌人内心（"对方无法理解 / 早已看穿"）；对手情绪只用主角能观察到的客观物理反应传达（发抖、瞳孔涣散、后退、失语）。
4. **禁「没有」排比烘托**——不用连续"没有X。没有Y。没有Z"硬抬冷酷感或气场，用正面、具象、动态的动作直接推进画面。
5. **禁精确字数判断**——正文不写"这八个字 / 四个小字"等对文字数量的精确判断（AI 易数错、改稿后易失准），除非数字本身是剧情信息。
6. **章末不靠作者腔硬抬**——钩子来自局面变化、风险逼近、结果未落地，不靠旁白宣布"大事将至 / 真正的危机才刚开始"。
7. **段落 2-5 句**——自然段落控制在 2-5 句；除对白外不要一行一句，也不要整屏长段。
8. **先发生再解释**——新设定 / 金手指 / 底牌不一出现就讲穿原理；先让事情发生、先给效果，原理随后续场景慢慢露出。

> 第 3、4 条另有 scanner 规则（`enemy_cognition_overreach` / `anaphora_stack`）在写文件后注入文风提醒（不阻断），文字门禁负责引导、scanner 负责提醒。第 8 条 scanner 只能抓局部解释句式（`explanation_marker`），抓不到"整段提前讲穿"这种结构问题，必须靠门禁兜。

## 2. `PROJECT.md`

建议最少包含：

1. 项目类型
2. 一句话卖点
3. 核心爽点 / 情绪点
4. 当前正式设定
5. 必须守住的写作原则
6. 默认协作规则
7. 建议项目文件

## 3. `STYLE.md`

建议最少包含：

1. 目标风格
2. 开头 / 黄金三章要求
3. 移动端段落与节奏规则
4. 对话与人物声音规则
5. 明确避免的 AI 味
6. 钩子原则
7. 信息释放原则
8. 配角认知原则
9. 战斗 / 冲突描写原则
10. 每章自检问题

重点：

- `STYLE.md` 不只是“想写成什么气质”
- 它还应承担**起稿阶段的护栏**
- 让 agent 在真正落正文时就带上：
  - 去 AI 味
  - 开篇卖点显形速度
  - 黄金三章 promise / payoff
  - 段落长短与移动端节奏
  - 信息不要讲穿
  - 章末不要靠作者腔硬抬

## 4. `资料/人物设定.md`

推荐 frontmatter：

```yaml
---
doc_role: canon_character
truth_status: confirmed
priority: 100
source_scope: project
---
```

建议最少包含（按优先级排列）：

### 4.1 核心三要素（必填）

- **欲望**：主角想要什么？（驱动力）
- **难点**：什么在阻碍他？（困境）
- **成就**：他能获得什么？（爽点承诺）

### 4.2 角色弧线（强烈建议填）

- **弧线类型**：废材逆袭 / 重生复仇 / 扮猪吃虎 / 升级流 / 自定义
- **谎言**：角色持有的错误信念
- **想要**：由谎言驱动的外部目标
- **需要**：真正能满足他的东西
- **幽灵**：造成谎言的过去创伤

（如有更多弧线细节，见 `references/creative-facilitation.md` 第二部分）

### 4.3 A面/B面（推荐）

- **A面（表面）**：别人看到的样子
- **B面（内在）**：真实一面，在什么条件下流露

### 4.4 基本信息

- 姓名、身份、起点
- 核心特征
- 核心缺陷 / 代价
- 语言风格（说话的方式、口癖、用词习惯）
- 核心外挂 / 优势

### 4.5 关键配角（可留待补充）

- 功能定位
- 与主角的利益关系
- 核心驱动力

### 4.6 关系网（可留待补充）

- 角色之间的利益关系
- 角色之间的信息差
- 关系的动态变化方向

## 5. `资料/世界规则.md`

推荐 frontmatter：

```yaml
---
doc_role: canon_world
truth_status: confirmed
priority: 100
source_scope: project
---
```

建议最少包含：

### 5.1 世界基调

- 世界类型（修仙 / 玄幻 / 都市 / 末世 / 其他）
- 一句话概括这个世界的核心规则

### 5.2 力量/修炼体系

- 大境界划分（3-6 个大境界）
- 每个境界的质变（不是量变——这个境界能做到什么前一个做不到的事）
- 突破条件
- 同境界战力差距由什么决定

### 5.3 金手指设定（如步骤 2B 已做深设，从那里同步）

- 核心概念与来源
- 功能模块（前期/中期/后期）
- 平衡性：代价、限制、副作用
- 进化路线

### 5.4 势力/组织

- 主要势力及其经济来源
- 势力之间的制衡关系
- 主角所在势力的运转逻辑

### 5.5 经济与资源

- 核心资源（灵石/灵气/其他）的来源和流通
- 资源的稀缺性等级

### 5.6 明确限制

- 不能乱改的硬边界
- 世界禁忌
- 强者为什么不直接碾压一切（权力制衡机制）

## 11. `预期.md`

推荐 frontmatter：

```yaml
---
doc_role: creative_anchor
truth_status: confirmed
priority: 120
source_scope: project
---
```

建议最少包含：

- **题材边界**：想写什么类型？绝对不碰什么？
- **核心体验**：读者看这本书最该获得什么体验？
- **个人执念**：一定要写进去的元素
- **风格方向**：想偏什么感觉？
- **初步设定**：已经想好的世界观/角色/机制（粗糙也行）
- **绝对不要**：讨厌的、绝对不想出现的东西

重点：

- 预期不是大纲，不是设定——它是"我为什么想写这本书"
- 它的价值在于**长篇写到中期回来翻一翻，确认方向没跑偏**
- 创意冲突时，选更接近预期的方向

## 12. `创作红线.md`

推荐 frontmatter：

```yaml
---
doc_role: creative_constitution
truth_status: confirmed
priority: 110
source_scope: project
---
```

建议最少包含：

- **通用红线**：所有章节必须遵守的底线（如：禁止水文、禁止降智、禁止无限制外挂）
- **项目特有红线**：本书特定的"绝对不能做"（根据题材和用户偏好）
- **风格红线**：绝对不能出现的表达方式或叙事手法
- **角色红线**：主角/核心配角绝对不能做的行为底线

重点：

- 创作红线是项目级的"最高法律"，所有后续写作和审稿都必须遵守
- 红线应该少而精，不要列一大堆——真正的底线才叫红线
- 和 `STYLE.md` 的区别：STYLE.md 管"应该怎么写"，创作红线管"绝对不能做什么"
