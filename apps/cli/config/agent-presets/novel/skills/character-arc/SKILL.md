# Character Arc — 角色弧线诊断

## 核心目标

回答一个问题：**这个角色为什么不好看？**

本 skill 不是从零设计角色（那是 `new-book-bootstrap` 的活），而是拿到一个**已有角色**，诊断他的内在旅程出了什么问题，并给出具体修法。

## 参考文件

- `references/arc-diagnostic-framework.md`：弧线类型定义、七项诊断清单、常见谎言库、弧线-结构映射表、网文弧线爽点校准、反模式库

---

## 步骤 0：收集角色信息

**必须先拿到材料再动手。**

读取顺序：

1. 用户指定的角色名 → 在 `资料/人物设定.md` 或其他人物设定文件中查找
2. 如果用户给了章节路径 → 读取章节正文，提取该角色的行为和对话
3. `PROJECT.md` → 了解故事整体走向
4. `STYLE.md` → 了解风格约束
5. 当前卷纲/章纲（如果有）→ 了解角色在大纲中的定位

**如果角色信息严重不足**（连名字、身份、基本设定都没有），直接告诉用户：
> "这个角色的基础设定太少，建议先用 `new-book-bootstrap` 建立角色档案。"

## 步骤 1：识别弧线类型

根据角色的故事定位，判断他属于哪种弧线：

### 传统弧线

| 弧线类型 | 核心动作 | 识别线索 |
|:---|:---|:---|
| **正向变化** | 相信谎言 → 面对 → 接受真相 | 角色在结尾和开头判若两人 |
| **负向变化** | 有成长潜力 → 堕落 → 被缺陷毁掉 | 悲剧结局，角色变得更糟 |
| **平坦弧线** | 已知真相 → 在考验中坚守 → 改变世界 | 角色没变，但世界因他而变 |

### 网文经典弧线

| 弧线类型 | 起点模式 | 核心爽点 |
|:---|:---|:---|
| **废材逆袭** | 被看不起/退婚/废修为 | 反差越大越爽 |
| **重生复仇** | 带前世记忆重生 | 布局清算的智商快感 |
| **扮猪吃虎** | 隐藏实力/装弱 | 揭露时的震惊反转 |
| **升级流** | 面临瓶颈/强敌 | 每次突破的递增爽感 |

**判定规则**：

- 如果用户已经在设定中明确了弧线类型 → 直接采用
- 如果没有 → 根据角色行为模式推断，并**询问用户确认**
- 如果角色兼有多种弧线特征 → 指出混合，建议用户确定主弧线
- 如果是配角 → 配角不一定需要完整弧线，但至少需要一个**功能定位**（镜像角色、催化剂、对照组）

## 步骤 2：七项诊断

**逐项检查**，每项给出"通过 / 存疑 / 未通过"：

### D1：弧线存在性

> "这个角色从开头到当前位置，内在有变化吗？"

- 如果行为变了但认知没变 → **只有情节，没有弧线**
- 如果实力变了但待人方式没变 → **数值膨胀，不是成长**（网文高频问题）
- 通过标准：能用一句话说清"角色从 X 变成了 Y"

### D2：谎言清晰度

> "角色相信什么是错的？"

- 如果答不上来 → 弧线缺少根基
- 如果谎言太泛（"我不够好"）→ 需要具体化到故事情境
- 参考 `references/arc-diagnostic-framework.md` 的常见谎言库匹配
- 通过标准：谎言能追溯到具体的幽灵（背景创伤）

### D3：想要≠需要

> "角色追求的东西和他真正需要的东西一样吗？"

- 如果一样 → 没有内在张力
- 差距越大 → 弧线张力越强
- 通过标准：能明确区分想要和需要，且两者之间有冲突

### D4：转变可信度

> "故事事件逼出了这个转变吗？"

- 角色变了但事件没要求这样变 → 强行转变
- 催化剂太弱（被说教就顿悟）→ 不够令人信服
- 通过标准：至少有一个事件直接挑战了角色的谎言

### D5：挣扎充分度

> "角色抗拒过改变吗？"

- 角色一下子就接受了真相 → 缺少挣扎，转变太轻松
- 重生文主角从不犹豫 → 复仇机器化
- 通过标准：至少有一个"加倍坚持谎言"的场景

### D6：弧线节奏

> "转变的节拍分布合理吗？"

- 铺垫太长、转变太急 → 前慢后赶
- 前 5 章就完成了弧线 → 太早，后面没有内在驱动力
- 网文弧线的爽点节奏是否递增
- 通过标准：弧线节拍与故事结构节拍有对应关系

### D7：展示 vs 告知

> "角色的变化是通过行动展示的，还是旁白告诉读者的？"

- "他终于明白了 XXX" → 告知，不是展示
- 角色用新的方式处理旧的困境 → 展示
- 通过标准：至少有一个"用行动证明转变"的场景

## 步骤 3：反模式扫描

在诊断过程中，同时检查以下反模式（详见 `references/arc-diagnostic-framework.md`）：

| 反模式 | 信号 | 适用范围 |
|:---|:---|:---|
| 被告知的弧线 | 旁白说"他变了"但行为没变 | 所有弧线 |
| 万能导师 | 改变全靠导师说教 | 所有弧线 |
| 创伤=转变谬误 | 因为受伤所以变了 | 所有弧线 |
| 完美主角 | 无缺陷、无谎言 | 所有弧线 |
| 瞬间顿悟 | 无铺垫突然领悟 | 所有弧线 |
| 数值膨胀代替成长 | 境界高了但人没变 | 升级流/废材逆袭 |
| 复仇机器 | 从头到尾只有复仇 | 重生复仇 |
| 全能无敌综合症 | 无真正威胁 | 升级流 |
| 降智陪衬 | 配角集体降智衬托主角 | 所有弧线 |

## 步骤 4：生成诊断报告

输出格式：

```markdown
# 角色弧线诊断：{角色名}

## 弧线类型
{类型}（{传统/网文}）

## 弧线要素
- **谎言**：{内容 / ⚠️ 缺失}
- **想要**：{内容 / ⚠️ 缺失}
- **需要**：{内容 / ⚠️ 缺失}
- **幽灵**：{背景创伤 / ⚠️ 缺失}
- **催化剂**：{事件 / ⚠️ 缺失}
- **挣扎**：{过程 / ⚠️ 缺失}
- **真相**：{认知 / ⚠️ 缺失}

## 七项诊断

| 检查项 | 状态 | 说明 |
|:---|:---|:---|
| D1 弧线存在性 | ✅/⚠️/❌ | {一句话} |
| D2 谎言清晰度 | ✅/⚠️/❌ | {一句话} |
| D3 想要≠需要 | ✅/⚠️/❌ | {一句话} |
| D4 转变可信度 | ✅/⚠️/❌ | {一句话} |
| D5 挣扎充分度 | ✅/⚠️/❌ | {一句话} |
| D6 弧线节奏 | ✅/⚠️/❌ | {一句话} |
| D7 展示vs告知 | ✅/⚠️/❌ | {一句话} |

## 检出反模式
- {反模式名}：{具体表现}
- …（无则写"未检出"）

## 修法建议
1. {优先级最高的修法}
2. …
3. …

## 建议下一步
{推荐接哪个 skill}
```

## 步骤 5：配角快检（如果用户问的是配角）

配角不一定需要完整弧线，但至少需要通过以下快检：

1. **功能定位清晰吗？**——这个配角在故事中的作用是什么？
   - 镜像角色（映射主角的另一种可能）
   - 催化剂（推动主角弧线的关键人物）
   - 对照组（用反面例子强化主角选择的意义）
   - 信息传递者（合理地向主角/读者释放信息）
   - 情感锚点（给主角提供情感动力）

2. **有独立动机吗？**——配角做事的理由是基于自己的立场，还是纯粹为了剧情需要？

3. **声音区分度够吗？**——如果遮住名字，能从对话中分辨出这是哪个角色吗？（此项如果有问题，接 `dialogue-diagnostics`）

4. **降智了吗？**——配角的行为是他知道的信息下的合理反应，还是为了衬托主角而故意犯蠢？

## 何时使用本 skill

✅ 用：
- "这个角色为什么不立体？"
- "主角感觉像升级机器，缺少人味"
- "角色转变太突然/太慢/不可信"
- "配角是不是太工具人了？"
- "我不知道这个角色到底相信什么"
- editorial-review 诊断报告指出角色问题后的深入分析

❌ 不用：
- 从零创建角色 → 用 `new-book-bootstrap`
- 对话写得不好 → 用 `dialogue-diagnostics`
- 角色没问题但章节推进无力 → 用 `scene-drive`
- 想直接改稿 → 用 `rewrite-to-style` 或 `chapter-execution`

## 不要做的事

- ❌ 不替用户选择弧线类型——提供分析，让用户决定
- ❌ 不强行要求每个角色都有完整弧线——平坦弧线和功能性配角都是合法的
- ❌ 不套用西方叙事理论否定网文弧线——废材逆袭、扮猪吃虎自有其结构逻辑
- ❌ 不在诊断中重写角色设定——诊断是指出问题，重写交给执行类 skill
- ❌ 不忽视用户已确认的设定——如果用户在 `confirmed` 中明确了角色特征，尊重它

## 和其他 skill 的关系

### 上游（谁会把用户送到这里）

- `editorial-review`：整稿诊断发现角色问题 → 接本 skill 深入分析
- `pacing-audit`：节奏诊断发现角色推进无力 → 可能是弧线问题 → 接本 skill
- `opening-review`：开头审稿发现主角不够吸引人 → 接本 skill 检查弧线铺设

### 下游（诊断完接谁）

- 如果角色对话声音同质化、缺少潜台词：
  - 接 `dialogue-diagnostics`
- 如果角色弧线没问题但章节推进无力、冲突设计有问题：
  - 接 `scene-drive`
- 如果角色弧线需要在大纲层面重新规划节拍：
  - 接 `outline-beat-design`
- 如果角色设定需要大改（不是微调，是重建）：
  - 接 `new-book-bootstrap`（角色部分）
- 如果诊断已清楚，用户要直接改稿：
  - 接 `chapter-execution` 或 `rewrite-to-style`
- 如果用户对诊断结果不认同或有补充：
  - 接 `skill-evolution`（记录反馈，沉淀偏好）

### 协作原则

- 本 skill 是**诊断型**——指出问题、给出修法方向
- 不执行改稿，不重写设定，不修改大纲
- 执行交给对应的执行类 skill

> 💡 如果用户对本次诊断有不同看法，可以提示：
> "要不要让 skill-evolution 记录一下这次的反馈？"
