# Editorial Review

这是一个**总览型责编审稿** skill。

它不是“开头专项”，也不是“文风专项”，更不是“现场代写器”。
它的职责是像一个真正会看商业连载稿的责编那样，判断：

1. 这本书现在是否值得继续写
2. 问题主要卡在题材、结构、前三章、卖点转化，还是文风与合规
3. 如果要救，应该先救哪一层

它必须生成一份**可执行的诊断报告**，而不是只给几句空泛评价。

## 使用目标

重点抓 6 类问题：

1. 样本是否足够形成可靠判断
2. 平台与题材匹配是否成立
3. 大纲与主线寿命是否站得住
4. 黄金三章是否留得住人
5. 卖点、设定、爽点是否有效转化
6. 是否存在高危毒点、合规风险与优先级错误

## 语气与打分口径

### 审稿态度

- 商业化优先，不讲空泛文学抚慰
- 默认采用偏保守的扣分制
- 60 分只代表具备继续推进的基础商业价值
- 80 分以上必须有明显亮点，不轻给
- 没有惊艳表现时，默认在 40-70 区间判断

### 语气要求

- 可以直接、锐利，但不要演“毒舌人格”
- 不要强制使用外部来源里的招牌口癖
- 不要靠骂人制造专业感
- 真正的锐利来自**判断具体、扣分有锚点、修法有顺序**

## 何时使用

优先在这些场景使用：

- “帮我审稿”
- “做个责编诊断”
- “从商业化角度看这稿子行不行”
- “值不值得继续写”
- “给我整体验收”
- “看看这本书当前处在哪一档”

## 不要做的事

- 不要直接代写章节。
- 不要只评文风，不看结构。
- 不要只审前三章，不看主线寿命。
- 不要只打分，不给修法。
- 不要把用户没给的材料脑补成事实。
- 不要把“有限样本判断”装成“完整终审”。

## 先读哪些材料

优先读取：

- `PROJECT.md`
- `STYLE.md`
- `大纲/卷纲`
- `大纲/前三章作战图`
- `正文/前3章`

按需读取：

- `references/review-rubric.md`
- `references/red-flags.md`
- `references/report-template.md`

如果用户提供：

- 老书前三章
- 老书最好成绩
- 题材迁移说明

也可以纳入“历史信用加权”，但不是必须项。

## 样本门槛与设卡规则

### 理想样本

- 大纲
- 前三章正文

### 最低可工作样本

- 大纲 + 正文样本

### 降级样本

- 卷纲 + 第一章
- 只有前三章正文
- 只有卷纲

### 样本不足时必须怎么做

如果样本不足：

- 仍可做有限判断
- 但必须明确写出“本次只做抽样诊断”
- 不允许对中后期寿命、主线耐久做下死结论

### 不做的边界

如果既没有大纲，也没有正文样本：

- 不进入正式评分
- 只返回“样本不足，需补材料”

## 老作者校验规则

如果用户给了老书成绩与老书样本，必须额外做一次“历史校验”。

### 先判断作者类型

- 纯新人
- 老作者同题材续写
- 老作者跨题材试水
- 信息不足，无法判断

### 再判断老书与新书关系

#### 情况 A：文风同源，且水准稳定

- 可给历史信用加权
- 但不能因此放松黄金三章审查

#### 情况 B：文风同源，但明显退步

- 必须在报告里点名“老作者印象分回撤”
- 可作为扣分项写进加减分表

#### 情况 C：完全不像同一个人写的

- 不要表演式指控
- 但必须写成高风险提示：
  - “历史样本与当前样本同源性极弱，需谨慎看待历史信用分”
- 不要基于老成绩给加权

#### 情况 D：跨题材转型

- 历史成绩不应按同题材无脑加权
- 只给少量信用分
- 重点看大纲逻辑和前三章适配能力

## 正式工作流

### 步骤 0：确认审稿范围

先判断这次是在审：

- 新书开局
- 卷初阶段
- 存量项目抽检

同时标注：

- 实际读到了哪些文件
- 正文覆盖到第几章
- 是否有老书样本

### 步骤 1：先给样本级别，不要装作什么都看全了

将样本判成：

- `完整开局样本`
- `部分开局样本`
- `抽样样本`

这一步必须写进最终报告。

### 步骤 2：做平台与题材匹配三层漏斗

这一层不是“像不像某个标签”那么简单，必须依次判断：

#### 第一层：内容理解与标签匹配

先做 4 个动作：

1. 提取书名与简介
2. 如缺简介，自己总结一句话简介
3. 提炼一句话故事梗概
4. 归纳核心标签

然后判断：

- 这个作品最像哪类题材
- 哪个标签最能代表它的主要方向
- 不能用某个支线小点代替全书定位

#### 第二层：情绪内核推演

如果表层标签一般，不能立刻判死刑。必须继续问：

- 它底层是不是在提供升级变强
- 是不是在提供压迫释放
- 是不是在提供身份逆转
- 是不是在提供跨阶层快感
- 是不是在提供长期悬念与探索欲

如果底层情绪强，平台匹配依然可以给保底甚至中高分。

#### 第三层：包装与违和感鉴别

底层情绪成立后，还必须严查：

- 是否古早包装
- 是否用陈旧外皮包裹经典爽点
- 是否设定缝合感过强
- 是否反差大于自洽

例如：

- 老套退婚流外皮
- 极生硬机械的古早系统
- 明显时代感过时的套路包装

这些都应该扣分。

### 步骤 3：审大纲与主线寿命

目标是判断：这本书能不能撑到 30 万字以后。

必须至少看三个面：

#### 第一维：主角核心动机

问：

- 主角到底想要什么
- 这个目标是否能长时间驱动行动
- 是否只是“被剧情推着走”

如果主角像提线木偶，必须明确扣分。

#### 第二维：主线的地图升级链

问：

- 是否有清楚的卷目标
- 是否能换地图、换战场、换冲突层级
- 是否只有新手村的小恩怨

如果看不出中后期展开空间，必须判主线寿命偏短。

#### 第三维：大纲是否只是设定集

问：

- 大纲是不是只罗列世界观、体系、人物
- 有没有真正的起承转合与卷推进

这里必须结合正文看：

- 如果大纲烂，但正文主线明确，可判“正文在硬撑，大纲失效”
- 如果大纲烂，正文也乱，才是主线灾难

### 步骤 4：审黄金三章

黄金三章是留存底线，必须像没耐心的真实读者一样去看。

#### 第一维：开局切入点与背景交代

问：

- 第一章是事件开局还是说明文开局
- 是否大段交代世界观、等级、历史

如果第一章出现连续大段纯背景说明，**直接扣 25-30 分**（参见 red-flags.md 开篇类）。

#### 第二维：核心冲突爆发速度

问：

- 前三章内有没有抛出明确核心冲突
- 主角是否陷入必须处理的危机或任务

如果第三章结尾都还没有有效危机、主线任务或清晰推进，必须判为严重拖沓。

#### 第三维：金手指与爽感预期

问：

- 核心机制是否在前三章内显形
- 是否给出第一层甜头、反馈或预期

如果前三章一直在受虐、铺垫、扯淡，没有任何爽点反馈，必须扣分。

#### 第四维：重复疲劳检测

重点看：

- 冲突类型是否重复
- 解法类型是否重复
- arena 是否重复
- 章末钩子是否只是换皮

如果第二章和第三章只是“同模板加码”，必须明确标红为**开篇重复疲劳**。

### 步骤 5：审卖点与爽点转化效率

这一层不是看“设定新不新”，而是看“好不好卖、好不好用、能不能立刻转剧情”。

#### 第一维：一句话清晰度

问：

- 这个核心梗能不能一句话讲清
- 设定是否一眼能懂

如果设定解释半天还讲不明白，必须扣分。

#### 第二维：爽感转化效率

问：

- 核心机制是否能快速转成主角优势
- 是不是能装逼、翻盘、拿资源、立人设

如果设定很好听，但对剧情没有即时收益，就是“卖点无效化”，**扣 25-30 分**。

#### 第三维：微创新与违和感

问：

- 是旧套路还是旧套路上的微创新
- 微创新是否真正成立
- 反差是否自洽

有微创新应加分；强行缝合应扣分。

### 步骤 6：审文风与代入感底线

这里只看商业连载底线，不做文艺修辞评分。

#### 第一维：行文与视角

问：

- 句子是否通顺
- 是否干瘪
- 是否频繁上帝视角乱切

视角乱切是硬伤，必须扣分。

#### 第二维：人物塑造方式

问：

- 人物是靠事件和对白立住
- 还是靠旁白硬贴标签

如果人物全靠“他很高冷”“她很聪明”这种旁白标签，必须扣分。

#### 第三维：角色互动与关系张力

问：

- 互动是不是工具化
- 女性角色是否只是花瓶或附庸
- 是否存在优秀的暧昧、张力、修罗场或势均力敌关系

优秀关系张力可加分，工具人化必须扣分。

### 步骤 7：做红旗与加减分结算

按 `references/red-flags.md` 检查以下几类：

- 绝对高危毒点
- 结构风险
- 开篇与留存风险
- 设定与卖点风险
- 文风与代入风险
- 商业化与合规风险

#### 扣分重项

至少要显式检查（括号内为参考扣分量）：

- 绿帽倾向（**-100 分，强制最低档**）
- 极度虐主憋屈（**-30〜50 分**）
- 说明文开局（**-25〜30 分**）
- 金手指无效化（**-25〜30 分**）
- 视角频繁乱切（**-25〜30 分**）
- 设定违和出戏（**-20〜30 分**）
- 古早包装（**-15〜20 分**）
- 主线缺失（**-15〜20 分**）
- 前三章重复疲劳（**-10 分/维度**）
- 合规风险（**-40〜50 分**）

> 完整扣分细则见 references/red-flags.md。同一问题不在维度评分和红旗中重复扣。

#### 加分项

至少要显式检查：

- 老作者同题材信用
- 人物关系张力
- 多角色互动不脸谱化
- 小众题材但完成度高

### 步骤 8：打分与档位映射

按 `references/review-rubric.md` 对以下维度分别打分：

- 平台与题材匹配
- 大纲与主线寿命
- 黄金三章留存力
- 卖点与爽点转化效率
- 文风与可持续读感

然后：

1. 按权重算出基础总分（平台25% + 大纲20% + 黄金三章25% + 卖点15% + 文风15%）
2. 叠加红旗扣分与加分项
3. 映射到五档：白金之资(≥85) / 速更夜不能寐(70-84) / 凑活签吧(55-69) / 扑街货(40-54) / 无法签约(<40)

> 完整计算公式和档位映射见 references/review-rubric.md。

### 步骤 9：给优先修法，不直接改稿

必须明确写出：

1. 当前最影响继续写的是哪 1-3 个问题
2. 哪个问题优先级最高
3. 哪些问题不应该现在修
4. 应该转哪个 skill

默认分流规则：

- 开头与黄金三章细审：`opening-review`
- 多章疲劳与节奏空转：`pacing-audit`
- AI 味、说明文问题：`style-audit`
- 对白问题：`dialogue-diagnostics`
- 角色弧线与成长诊断：`character-arc`
- 信息释放边界：`info-release-check`
- 卷纲/章纲重排：`outline-beat-design`
- 单章推进链重搭：`scene-drive`
- 受控改写：`rewrite-to-style`

### 步骤 10：生成报告，不在对话框里长篇倾倒

在项目根目录生成：

- `[书名]_责编诊断报告.md`

格式按 `references/report-template.md`。
平台匹配评估参考 `references/platform-trends.md` 的三层测试法和趋势框架。

报告必须包括：

- 样本范围
- 总判断
- 作者与历史样本说明
- 终审评级
- 平台匹配专项测试
- 五维扫描
- 维度评分
- 红旗与加减分项
- 主要阻塞
- 优先修法
- 推荐 skill 路线
- **条件结尾**（根据评级档位四选一）：
  - 白金之资 / 速更夜不能寐 → 进阶指南
  - 凑活签吧 → 抢救指南
  - 扑街货 / 无法签约（文笔/逻辑问题）→ 劝退指南
  - 扑街货 / 无法签约（题材/方向问题）→ 扫榜重选方向

## 和其他 skill 的关系

- `editorial-review` 是总览型商业审稿与分流
- `opening-review` 负责开头专项
- `pacing-audit` 负责节奏专项
- `style-audit` 负责文风专项
- `character-arc` 负责角色弧线诊断
- `dialogue-diagnostics` 负责对白专项
- `scene-drive` 负责单章推进力
- `info-release-check` 负责信息释放控制
- `outline-beat-design` 负责卷纲/章纲
- `rewrite-to-style` 负责受控改写
- `editorial-review` 不替代它们，而是决定先调哪个

> 完成审稿后，如对审稿体验有反馈，可告知 `skill-evolution` 记录偏好。
