# Info Release Check

不是泛泛地说“少解释一点”。

它专门判断：

- 哪些信息现在必须给
- 哪些现在只能给效果、迹象、反应，不能讲穿
- 哪些应该后置
- 哪些已经说多了，正在透支后面的爽点、钩子或翻转

## 核心目标

重点抓 5 类问题：

1. 原理先于效果
2. 解释先于冲突
3. 配角替读者补课
4. 对话承担设定说明书
5. 章末或中段把后续价值提前说破

## 何时使用

优先在这些场景使用：

- “这章是不是解释太多了”
- “哪里把设定讲穿太早了”
- “为什么爽点感觉被透支了”
- “这段对话像在讲课，帮我看看”
- “这一条信息线应该什么时候揭示”
- “先别改稿，先看信息释放顺序对不对”

## 不要做的事

- 不要把它做成泛化的文风审稿。
- 不要把所有说明都判成错误。
- 不要只盯单句，而忽略这条信息线在后文还有没有价值。
- 不要直接重写整章。
- 不要把“暂时不解释”误做成故弄玄虚。

## 先读哪些参考

按需读取：

- `references/info-release-checklist.md`
  - 默认主参考

## 工作流

### 步骤 0：确认审的范围

先判断这次是在审：

- 单章
- 连续 2-5 章
- 某条具体信息线

常见信息线包括：

- 金手指原理
- 世界规则
- 反派真实意图
- 主角底牌
- 关键关系真相

### 步骤 1：先判断“这条信息的价值是什么”

至少先说清：

1. 这条信息解决当前什么问题
2. 这条信息未来还能兑现什么
3. 如果现在讲穿，会透支什么

如果第三条说得很重，就不能现在讲满。

### 步骤 2：把信息分桶

默认分成 4 桶：

1. `现在必须给`
2. `现在只给效果 / 迹象 / 反应`
3. `现在不能讲穿，需后置`
4. `已经说多了，建议删或改写`

这里的关键不是“给不给”，而是：

- 现在给什么层级
- 谁来给
- 用动作、结果、反应给，还是用解释给

### 步骤 3：检查是否出现高风险释放方式

重点看：

- 旁白先讲原理，故事还没跑起来
- 配角替读者总结主角路线
- 对话互相讲彼此都知道的事
- 风险刚抬起，旁白先说“这意味着什么”
- 章末把下一步价值直接宣布掉

### 步骤 4：检查信息是不是顶替了推进

先问：

1. 这一段删掉解释后，故事还动不动
2. 当前冲突是不是被解释打断了
3. 这条信息现在不讲穿，读者还能不能跟得上

如果答案是：

- 故事明显更顺
- 冲突被解释吃掉
- 读者其实能跟上

那通常就是解释超额了。

### 步骤 5：检查“爽点 / 钩子 / 翻转”有没有被透支

重点判断：

- 爽点还没兑现，原理是否已经先讲完
- 钩子还没落地，下一步价值是否已被说破
- 翻转还没发生，角色或旁白是否已经提前做出完整判断

### 步骤 6：输出修法，不直接改稿

输出时优先说明：

1. 哪条信息线出了问题
2. 主要故障属于哪类
3. 现在该留什么
4. 现在该删什么
5. 哪些只能改成效果 / 反应 / 后果
6. 该接 `style-audit`、`scene-drive`、`chapter-execution`，还是停在 review

## 判断边界

### 什么时候不要误判成“解释过多”

- 这是当前冲突成立所必需的最小信息
- 读者如果现在不知道，连局面都看不懂
- 这是角色视角天然会立刻想到的判断，且没有把未来价值说光

### 什么时候一定要判为高风险

- 新设定首次出现就完整讲穿
- 配角太早替读者解释完主角路线
- 对话在给读者补课，而不是在交锋
- 章末把后续兑现价值直接说破
- 一条信息刚露头，就把效果、原理、结论一次性全讲完

## 和其他 skill 的关系

- 局部文风 / AI 味 / 对白审稿：`style-audit`
- 单章推进链 / 章末落点设计：`scene-drive`
- 多章节奏 / 追读审稿：`pacing-audit`
- 受控改写表达层：`rewrite-to-style`
- 真正改稿：`chapter-execution`

默认关系是：

- `info-release-check` 负责判断哪些信息现在该给到什么层级
- `style-audit` 负责看这些问题在句子和对白层面怎么表现出来
- `rewrite-to-style` 负责按这些边界去改写表达
- `scene-drive` 负责把单章的释放边界嵌回推进链
- `chapter-execution` 负责真正落稿
