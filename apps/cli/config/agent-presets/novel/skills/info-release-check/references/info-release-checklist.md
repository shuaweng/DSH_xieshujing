# Info Release Checklist

## 一、先看这条信息的价值

先问：

1. 这条信息现在解决什么理解问题
2. 这条信息后面还能兑现什么
3. 现在讲穿会不会透支爽点、钩子、翻转或人物判断

## 二、四桶分法

### 1. 现在必须给

- 不给就看不懂当前冲突
- 不给就不知道角色为什么这样做

### 2. 现在只给效果 / 迹象 / 反应

- 先看到异常
- 先看到后果
- 先看到别人看不懂、但挡不住

### 3. 现在不能讲穿，需后置

- 原理一讲就会把后续价值说光
- 角色现在本来也不该完全看懂
- 读者现在只需要知道“有问题”，不需要知道“全答案”

### 4. 已经说多了，建议删或改写

- 一次性把效果、原理、结论都讲完
- 配角把主角路线替读者讲明白
- 对话互相解释彼此都知道的设定

## 三、高风险释放方式

### 1. 原理先于效果

- 先解释机制，再让事情发生
- 爽点还没落地，原理先讲完了

### 2. 解释先于冲突

- 冲突刚开始就停下来讲课
- 局面刚有张力就被旁白总结掉

### 3. 对话补课

- “如你所知”式说明
- 角色互相讲他们本来都知道的事
- 台词不是交锋，是在替作者发 handout

### 4. 配角提前看穿

- 主角路线、底牌、心思太早被别人完整看懂
- 读者还没爽到，旁人已经先给结论

### 5. 章末宣告式说破

- “但他们不知道的是……”
- “真正可怕的是……”
- “他很快就会明白……”

## 四、检查是不是顶替了推进

- 这段删掉解释后，故事会不会更顺
- 这段信息有没有让当前冲突停住
- 这段是不是把“发生”换成了“讲解”

## 五、检查是否透支后续价值

- 后面的爽点是否被现在说破
- 后面的翻转是否被现在抢答
- 后面的钩子是否被现在提前解释掉
- 后面的关系变化是否被现在直接定义完

## 六、优先修法

1. 先删完整解释
2. 再改成动作 / 结果 / 反应 / 后果
3. 再决定哪些判断后置
4. 最后才修措辞和段落
