# Agent Note：显式小说分析与输入位置

Status: implemented

[English](2026-08-27-novel-explicit-analysis-and-composer-placement.md) | 中文

## Problem

打开章节审查抽屉时，如果没有旧报告，系统会同时启动高成本的审稿 Subagent，导致查看与执行无法区分。确定性 NOAI 分析只采用了既有 Novel guard 的少量规则，遗漏常见的先解释后呈现、视角越界与模板化表达。选区引用总是追加到输入框末尾，即使作者已把光标放在别处。Revision 绑定的分析报告已经持久化并能在工作台显示，却没有模型工具入口，迫使作者把报告复制进对话。

## Decision

打开章节审查抽屉只读取该章节精确 Revision 的现有报告。空抽屉展示明确的“开始审查”操作；已有报告展示明确的“重新审查”操作。只有点击这两个操作时才会保存脏正文并启动审稿。NOAI 仍是点击即运行的确定性扫描，并使用从持续维护的 Novel guard 提炼出的包内规则集；报告语义变化时必须更新分析器版本。

对话输入服务为每个 Session 保存当前文本框选区。外部引用生产者请求服务在该选区插入结构化引用。输入状态机仍拥有引用 occurrence、撤销单元、序列化与 draft Revision 校验；DOM 层负责报告选区变化并恢复插入后的光标。

分析报告继续作为 Revision 绑定的派生产物，而不是作者资产。只读 `novel_get_analysis` 工具解析规范 Asset 引用，并返回这些精确 Revision 上持久保存的章节审查或 NOAI 报告。报告不会被静默加入 Context Manifest，不出现在作者资产搜索中，也不能通过小说工具修改。

## Alternatives considered

**打开抽屉时自动生成审查。** 不采用，因为导航手势会启动模型工作、产生延迟与成本，还可能在作者没有明确操作时覆盖当前报告。

**所有外部引用都追加到草稿末尾。** 不采用，因为这会打断句子组织，并迫使作者手动移动每条引用。

**把报告暴露为普通类型化 Asset。** 不采用，因为报告由一个精确 Revision 派生，并拥有独立的替换与来源规则；把它当作作者文件会混淆分析历史与作者内容。

**把最新报告自动注入每轮 Prompt。** 不采用，因为无关任务也会消耗上下文，还可能收到错误 Revision 的报告。显式工具读取会保留在 Session 历史中，并让报告选择过程可见。

## Consequences

作者可以在不启动任务的情况下查看审查面板，自主决定何时审查，把引用插入正在写作的位置，并让 Agent 按章节精确 Revision 读取持久报告。更完整的确定性规则会产生更多发现，因此必须保持分类可解释、结果有界并更新版本，而不能把它包装成概率式作者身份检测器。客户端输入选区成为共享状态，因为引用生产者若不查询其他插件的 DOM，就只能通过该状态遵循实时光标。
