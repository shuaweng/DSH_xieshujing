# Agent Note：小说标题原子变更与 Markdown 阅读视图

状态：已实现

[English](2026-08-27-novel-atomic-title-and-markdown-reading.md) | 中文

## 问题

小说资产把作者可见标题保存在类型化 Frontmatter 中，把正文或策划文本保存在正文区。原有提案操作只能修改正文，因此 Agent 可以填充空章节，却仍留下“未命名章节”；随后再提交标题提案时，又会基于已经过期的 Revision。自由文本指导资产也只展示 Markdown 源码，普通阅读时标题、列表和强调会直接显示成符号。

## 决策

共享小说操作词汇新增 `update-title`，由已注册资产类型校验和物化，而不是由通用 Repository 解释。内置正文和自由 Markdown 类型在一个精确 Revision 的 ChangeSet 中最多接受一个标题操作和一个正文操作。正文资产的内容操作是 `insert-text` 或 `replace-text`；策划与书本指导资产的内容操作是 `replace-text`。两项变更只序列化和发布一次，因此新章节名与正文要么共同成为一个 Revision，要么都不生效。

`update-title` 只修改类型拥有的作者可见标题，不能修改任意 Frontmatter、身份、父级、类型或派生元数据。现有精确 Revision 冲突、审阅、应用和恢复语义保持不变。

自由 Markdown 资产继续只把 Markdown 源码作为作者内容真相。客户端对已有内容默认展示渲染后的阅读投影，并提供明确的“编辑/阅读”切换。编辑模式展示未改变的源码，并沿用现有受保护的完整内容保存；阅读模式不会创建或持久化第二份表示。

小说工作台 Prompt 与章节执行 Skill 指示 Agent：为既有未命名章节命名并填充内容时，把 `update-title` 与对应正文操作放入同一提案。直接创建章节仍可在一次 `novel_create` 中提交标题和完整正文。

## 考虑过的替代方案

**把章节名写进正文标题。** 不采用，因为资源树标签、引用、搜索元数据与工作台标题读取的是类型化资产标题，而不是第一个 Markdown 标题。

**分别创建标题和正文 ChangeSet。** 不采用，因为第一项应用后会创建新 Revision，使第二项立即过期；自动重定位又会削弱精确 Revision 保证。

**增加通用元数据 Patch。** 不采用，因为这会让模型输入绕过类型拥有的身份、层级与 Frontmatter 规则。

**在 Markdown 旁持久化渲染 HTML。** 不采用，因为两份作者表示可能分叉。渲染只作为保留 Markdown 源码的客户端投影。

## 结果

Agent 现在可以通过一个可审阅提案，同时为既有空章节命名并写入正文，Diff 卡片也会同时展示两项变化。作者仍保留原有标题和正文编辑能力。本书概述、本书风格、大纲、卷纲和章纲默认按格式化文档阅读，同时保留自由 Markdown 编辑和现有文件格式。
